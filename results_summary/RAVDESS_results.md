| 项 | 值 |

| batch size | 64（有效 batch 256，梯度累积 4） |
| 优化器 | Adam，lr = 1e-3 |
| repeat 次数 | 3（Mean±STD 为 3 次 repeat 统计，seed = 42 / 1042 / 2042） |
| 结果文件 | `192.168.1.30:/root/fl/result_path/RAVDESS/Speaker/<algo>/AUDIOCNNRNN/20Clients/1.txt(.json)` |
| 记录日期 | 2026-10-19 |

说明：JSON 的 `experiment_config` 中 `sensitive_attribute` 字段仍写作 `"race"`（沿用的旧字段名），
但 RAVDESS 数据管线实际按演员编号奇偶生成性别标签（`module/dataset.py: get_RAVDESS_dataset`），
本表按真实生效的“性别”口径记录。

指标定义：

- **ACC**：整体准确率
- **ACC_gap**：各受保护组准确率的极差（max − min）
- **DEO**：|TPR(A=0) − TPR(A=1)|，即均等机会差
- **SPD**：P(ŷ=1|A=0) − P(ŷ=1|A=1)，即统计均等差

数据完整性：16 个算法目录全部存在，`1.txt.json` 与纯文本摘要均齐全，无缺格；JSON 自带 HM，
与按每次 repeat 逐对 `harmonic_mean(ACC_i, 1 − DEO_i)` 重算的结果一致（差异 < 1e-16）。

> **重要提示（先于任何排名阅读）**：本次 16 个算法全部退化为常数预测器。
> 15 个算法恒输出正类（ACC 恰为测试集正类占比 32/240 = 0.1333），
> `LoGoFair` 恒输出负类（ACC 恰为负类占比 208/240 = 0.8667）。
> 全部算法的 ACC_gap / DEO / SPD 均为 0、3 次 repeat 的 STD 均为 0。
> 因此下表的排序只反映“塌缩到哪一类”，**不能作为算法精度或公平性的比较证据**。

HM 指标说明：`HM = harmonic_mean(ACC, FR)`，其中 `FR = 1 − DEO`，与 `algorithm/*.py` 中
`FR = 1-DEO; HM = get_HM_by_two_value(accuracy, FR)` 的定义一致。HM 由每次 repeat 的
(ACC, DEO) 逐对计算后再取 Mean±STD，数据来源为各格子的 `1.txt.json`。

**注意**：所有 HM 均为虚高或失真。15 个恒正类算法的 `HM = harmonic_mean(0.1333, 1.0) = 0.2353`；
`LoGoFair` 的 `HM = harmonic_mean(0.8667, 1.0) = 0.9286`，是因为全负类预测使 DEO = 0（FR = 1）。
不能把 `LoGoFair` 的 0.9286 当作“最公平/最好”的证据。

## 关键观察

1. **16 个算法全部退化，有效算法数为 0**：15 个算法（FairFed、FedAvg、FedFB、FedFair、FedNova、
   FedProto、FedProx、FedRenyi、FedRep、FederatedAverageWithPo、FL_FairBatch、mFairFL、PDFFed、
   PDFFed_DP、Scaffold）的 ACC 精确等于测试集正类占比 32/240 = 0.1333，且 ACC_gap / DEO / SPD
   全为 0、3 次 repeat 的 STD 全为 0，即恒输出正类的常数预测器；`LoGoFair` 的 ACC 精确等于
   负类占比 208/240 = 0.8667，是恒输出负类的常数预测器。两者都未学到任何判别信息。
2. **PDFFed / PDFFed_DP 的正确读法**：按原始数值，PDFFed 与 PDFFed_DP 的 ACC = 0.1333±0.0000、
   HM = 0.2353±0.0000，在 16 个算法中并列第 2（15 路并列），仅“低于” LoGoFair 的 0.8667/0.9286；
   与并列者的差距为 0.0000。STD = 0.0000 并非“稳定领先”，而是每次 repeat 都塌缩到同一个常数预测，
   因此“领先幅度”和“稳定性”都不具备算法学含义。以有效算法数为分母时，答案只能是 **0 个有效算法，
   排名不可用**。
3. **退化有日志佐证**：以 PDFFed 为例，从 Communication 1/200 到 200/200 的每一次评估都输出
   `per-group accuracy: {0: 0.13333, 1: 0.13333}`、`ACC: 0.133, DEO: 0.0`；本地训练日志中的
   `Origin task loss` 始终停留在 0.70–0.73（二分类随机水平约 0.693），说明模型基本未更新。
   同时单个 repeat 的 GPU 时间仅 65 s（PDFFed）/ 15 s（FedAvg），与 200 轮 × 1,200 样本 ×
   2 个本地 epoch 的训练量明显不匹配（对照：LoGoFair 为 1,553 s/repeat，确实在训练，但仍塌缩为全负类）。数据侧已核查：音频缓存形状 (1200, 300, 64) / (240, 300, 64)，
   样本标准差约 0.25、无零方差样本，标签分布正常（每演员 52 负 + 8 正），故不是特征为空所致；
   `Speaker` 划分也已核对为 20 × 60 训练样本、4 位测试演员，修复记录与上表一致。
4. **与 CREMA-D / Speaker / K=20 的横向对比**：在 CREMA-D 上，同一批算法的 ACC 为 0.658–0.859，
   PDFFed 0.809±0.022 排 16/16（未退化算法中最后），HM 0.875±0.011 排第 10/16（剔除 3 个退化算法后
   第 7）；可见 CREMA-D 上 PDFFed 确实不领先。RAVDESS 本轮所有算法同时塌缩，**无法提供**
   “PDFFed 是否领先”的任何证据——这不是“PDFFed 在 RAVDESS 上领先”，而是整套 RAVDESS 实验失效。
   由于同一份代码在 CREMA-D 上能正常收敛（ACC 0.81–0.86），问题更可能出在 RAVDESS 音频管线
   （特征/输入布局或归一化），而非算法本身；“CREMA-D 上 PDFFed 不领先”的担忧仍需修复重跑后才能回答。
5. **小样本敏感性未能体现，反而被塌缩掩盖**：划分修复后每客户端恰 60 条训练样本，其中仅 8 条正类
   （52 负 + 8 正），batch 64 已覆盖整个客户端，正类样本稀缺，理论上 repeat 间波动应偏大。
   但实测所有格子的 STD 均为 0.0000，说明 3 次 repeat 不是“稳定复现”而是“稳定失败”；
   本轮数据无法用于评估 24 演员 / 20 客户端带来的小样本方差，需在修复音频管线后重新观察。

## 复现命令要点

```bash
python main_AUD_CLF.py \
  -dataset RAVDESS -split_strategy Speaker -task AUD_CLF -model_type AUDIOCNNRNN \
  -num_clients_K 20 -communication_round_I 200 -algorithm_epoch_T 2 \
  -batch_size 64 -test_batch_size 64 -test_eval_freq 50 \
  -optimize_method adam -learning_rate 0.001 \
  -exp_repeat_times 3 -parallel_repeats 1 -base_seed 42 -resume
```

结果汇总前需先确认模型不再退化为常数预测器（检查日志中 `per-group accuracy` 是否随轮次变化、
`Origin task loss` 是否显著低于 0.693），否则本表数值不具可比性。
