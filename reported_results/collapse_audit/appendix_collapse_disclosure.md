## 1. 一句话结论

在 **ADULT** 与 **DRUG** 上，本次基准涵盖的 **40 / 16 个联邦算法、89 / 218 个实验格**，
**没有任何一格**的准确率超过「恒定预测多数类」这个平凡基线 1 个百分点以上；
**BANK** 只有 5 个算法（PDFFed、PDFFed_DP、FedProx、mFairFL、FederatedNova）能勉强越线。
这不是 PDFFed 的缺陷，而是**数据集本身的高类别不平衡 × 联邦异构切分**共同导致的
**表示坍缩（representation collapse to majority class）**：所有方法一起失效。
作为对照，**COMPAS**（224 格中 177 格越线，最好 +8.37pp）与 **DUTCH**（159 格中 131 格越线，
最好 +28.79pp）在同样的 Dirichlet 切分下仍然可学，说明失效条件是「高地板」而非「异构」本身。

## 2. 判据定义

- **地板 floor** = 该数据集**测试集**中多数类的占比。恒定预测多数类的分类器准确率恰为 floor，
  其 DEO / ACC_gap 等组间公平指标恰好为 0（因为预测与敏感属性无关）。
- **坍缩格（collapsed）**：`ACC ≤ floor + 1pp`。1pp 阈值取自「1 个百分点以内的提升在该测试集
  规模下不具备统计意义」。
- **超额正确样本数 excess_correct** = `round(ACC × n_test) − majority_n`，即比恒定多数类预测器
  **多答对的测试样本个数**。这是比百分点更硬的指标，不受测试集规模影响。

## 6. 机制解释（写进论文的说法）

坍缩需要**两个条件同时成立**，缺一不会发生：

1. **高地板（类别极不平衡）**：ADULT 76.4%、BANK 87.8%、DRUG 78.9% 的测试样本属同一类。
   此时「全预测多数类」已经是一个准确率很高的解，损失曲面上存在一个又深又平的坏极小值。
2. **客户端内标签分布退化（强异构切分）**：Dirichlet(0.1/0.5/1) 切分后，多数客户端的本地
   数据只含单一类别，本地梯度方向一致地指向「预测该类的多数标签」，聚合后全局模型被拽向
   恒定预测器；同时组间公平损失（DEO 类正则）在此解上**恰好为 0**，
   因此公平性正则不但不抵抗坍缩，反而会**奖励**它 —— 这解释了为什么 87/89 个 ADULT 格
   和 4/218 个 DRUG 格出现 DEO ≡ 0 的「完美公平」。

对照组证明了第 1 个条件是决定性的：COMPAS（地板 0.5397）与 DUTCH（地板 0.5223）在
**同样的 Dirichlet01 强异构**下依然有 20–29pp 的可学空间，177/224 与 131/159 格越线。
换言之，**「不均匀」不是废品判据，「高地板 + 不均匀导致的坍缩」才是**。

代码侧的对应措施已存在但**未在这批运行中启用**：`main_Tabular_CLF.py` 提供
`-balance_sampling`（按标签逆频率的 `WeightedRandomSampler`），默认 0；
本次审计的 788 格中 783 格的 `experiment_config` 未记录该键、5 格记录为 `0`，
**没有一格是 1**。因此这批 BANK/DRUG/ADULT 结果是在「未做客户端内标签重采样」条件下取得的，
应作为负面结果披露，而不应与 COMPAS/DUTCH 的正面结果混在同一张主表里。

### 9.0 结论先说

把 176 个「同一格有多份结果」的拷贝对按（是否同机 × 是否同 commit × 数值是否一致）三分：

| 拷贝对类型 | 对数 | 其中数值不一致 |
|---|---|---|
| 跨机 + **不同 commit** | 167 | **76** |
| 跨机 + **相同 commit** | **0** | **0** |
| 同机 + 相同 commit | 9 | **6** |
| 合计 | 176 | 82 |

三条硬结论：

1. **不存在「同一份代码、两台机器、结果不同」的情况** —— 跨机同 commit 的拷贝对数为 **0**。
   所有跨机分歧都伴随 commit 不同（9.1）。
2. 78 个「不一致格」中，**只有 5 格会翻转越线判定，占 788 格的 0.6%**；
   其余差异不改变本附录任何一条结论。
3. 同机、同 commit、**同划分指纹、同随机种子**仍有 6 对不一致 —— 这是训练路径的
   **残余非确定性**，与数据版本和代码版本都无关（9.2）。

### 9.1 跨机分歧的真正原因 = 代码版本混用，不是「不可复现」

- 170 个格在两台机器上各有一份结果，其中 **78 份不一致**（71 份 ACC 不同、7 份仅 DEO 不同）。
  ΔACC 中位数 0.0021，均值 0.0213，最大 0.3987（`BANK/Uniform/FedProx`：
  .30 @ `951792035` = 0.8806 vs .31 @ `e34c32ad3` = 0.4819）；ΔACC > 5pp 的有 10 格。
- 按 commit 拆分：**75 格两侧 commit 不同；跨机同 commit 的不一致格为 0**；
  另 3 格是同机重复（见 9.2）。
- 788 个保留格来自 **8 个不同 commit + 28 格无 commit 记录**：

  | commit | 保留格数 | 覆盖最全的数据集（算法数 / 行数） |
  |---|---|---|
  | `e4f45401b` | 264 | BANK 15/51、DRUG 16/107、COMPAS 16/104、DUTCH 15/134 |
  | `4dc887b67` | 214 | DRUG 12/96、COMPAS 12/94、DUTCH 7/24 |
  | `e34c32ad3` | 185 | **ADULT 15/60**、BANK 13/51、COMPAS 14/54、DUTCH 15/37 |
  | `951792035` | 36 | 零散补格 |
  | `6da33067b` | 35 | 零散补格 |
  | (blank) | 28 | **ADULT 28 算法 × 1 split**（早期未记录 commit） |
  | `ce59163a3` | 16 | 零散补格（= PR #62 合并提交，落后 main 8 个 commit） |
  | `c522dca6e` | 10 | 零散补格 |

- 成因：worker 是**长寿命进程**，在启动那一刻记录 HEAD 并写入之后每一份结果；
  仓库随后被推进，旧 worker 仍继续用旧代码产出。仅 10-21 一天，.30 写出的 json 就横跨
  7 个 commit（`e4f45401b`×57、`951792035`×32、`0ada0275b`×31、`6da33067b`×17、
  `ce59163a3`×6、`754c44326`×3、`c522dca6e`×2），.31 同样横跨 7 个。
- **⟹ 正确口径不是「重跑这 78 格」，而是「按单一 commit 出表」。**
  推荐：**BANK / DRUG / COMPAS / DUTCH 用 `e4f45401b` 单版本表**（15–16 个算法齐全）；
  **ADULT 用 `e34c32ad3`（15 算法）或 (blank) 批次（28 算法）**，二者不可混排。
  同一张表内选数规则统一为「同格取 `recorded_at` 最新的一份」，并把该规则写进方法节。

**注意时间线**：这 6 对的两份记录都落在 **10-18 至 10-20**，而 DUTCH.pickle 的工作树
mtime 是 **10-21 17:58** —— 重写晚于全部分歧记录，**不可能是其成因**（旧版此处推断有误）。

**引用要求**：这 6 格如需进正文，须补足重复次数并报区间，不得只取其中一份。
其中 2 格（`COMPAS/Dirichlet05/FederatedRenyi`、`COMPAS/Uniform/FederatedRenyi`）
会因取值不同而翻转越线判定。

### 9.4 一次运行内的 3 次重复跨越了不同划分（真实缺陷，7 例）

`partition_fingerprints` 按重复逐条记录。有 **7 份 json 的 3 个指纹互不相同**
（DRUG 4 份、COMPAS 3 份，全部集中在 10-16 04:36 → 14:52，commit 均为 `e4f45401b`）。
含义：这 7 次运行的 3 次重复各自重新生成了一次客户端划分，聚合出的 mean/std
**混用了不同数据划分**。该时间窗与 COMPAS/DRUG 的缓存版本切换（10-16）重合，
属版本切换期的边界现象。
**处置**：这 7 份结果不应引用；如需该格数据，重跑即可。

### 9.5 BANK.pickle 未纳入版本管理（但语义一致，结果可比）

`dataset/BANK/BANK.pickle` 在两台上都是 **untracked**（`git show HEAD:` 为空），
工作树 md5 互不相同（.30 `af38d8b9f733` @10-19 11:41 / .31 `716ce9a2ca37` @10-17 06:35）。
但两者 size 同为 17297620，且**语义指纹完全一致**：
`train_sha=d3d77b2672fd / test_sha=92978e9dd696`、测试标签 `20bb0b3f447d0e3f`、

⟹ **BANK 的 184 份结果跨机完全可比**，md5 差异只是非语义字节。

### 9.7 选数规则不变性（说明无需也不应挑数）

对全部算法统一施加四种同格选数规则，PDFFed / PDFFed_DP 的排名**不随规则改变**：

| 数据集 | newest（取最新） | max（取最大） | min（取最小） | mean（取均值） |
|---|---|---|---|---|
| BANK | #1 PDFFed 0.8976、#2 PDFFed_DP 0.8968 | 同左 | 同左 | 同左 |
| COMPAS | #1 PDFFed_DP 0.6234、#2 PDFFed 0.6158 | #1 PDFFed_DP 0.6234、**#2 FederatedAverageWithPo 0.6165**、#3 PDFFed 0.6158 | 同 newest | #2 FederatedAverageWithPo 0.6161 |
| DUTCH | #1 PDFFed_DP 0.8103、#2 PDFFed 0.8052 | 同左 | #2 FederatedAverageWithPo 0.7945、#3 PDFFed 0.7939 | #2 PDFFed 0.7977 |
| ADULT | 全 28/40 算法 meanACC 恰为 floor，越线 0 格 | 同左 | 同左 | 同左 |
| DRUG | #1 FederatedRenyi 0.7946、#4 PDFFed 0.7817，越线 0 格 | 同左 | 同左 | 同左 |

两条读法：

1. **挑数救不回 ADULT 与 DRUG** —— 这两个数据集在任何规则下都是 **0 格越线**，
   最好成绩分别等于地板、以及仅比地板多 2 个样本。
2. **「取最大值」这条规则反而会削 PDFFed**：COMPAS 上 `max` 让
   FederatedAverageWithPo（0.6165）超过 PDFFed（0.6158）。
   即「报对自己最有利的数」并不是一个稳定策略，它同时也会抬高对手。

因此本基准采用**事前固定的规则**（单 commit + 单数据版本 + `newest`），
而不是事后按方法挑数；9.1–9.4 列出的全部异常照常披露。
